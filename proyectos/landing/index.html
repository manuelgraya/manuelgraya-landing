Web · Pixel art

Una web personal hecha píxel a píxel, y servida a la antigua

La landing de manuelgraya: HTML estático, Tailwind compilado y casi nada de JavaScript, con un fondo WebGL, un diálogo de RPG en «Sobre mí» y un formulario que corre sobre un microservidor en Python sin dependencias.

Por Manuel Graya · Lectura: 3 min

Las webs personales suelen salir de una plantilla. Esta empezó como un diseño en Google Stitch y se reconstruyó a mano para que todo se compile en local: HTML estático, Tailwind CSS compilado y guardado en el repositorio, y ningún paso de build en el servidor. El servidor solo sirve archivos, como en los viejos tiempos.

Nació el 17 de julio de 2026 y lleva más de cincuenta commits. Este periódico que estás leyendo es su última incorporación.

Menos JavaScript, más CSS

Toda la web funciona con cuatro scripts pequeños, sin frameworks. El menú del móvil, las pantallas de carga, las animaciones al hacer scroll y el botón de «ver más» están hechos solo con CSS. El fondo es un shader WebGL: una rejilla de píxeles que late y se ilumina al paso del ratón. Si el navegador no tiene WebGL, desaparece sin más; si prefieres menos movimiento, se queda en un fotograma quieto.

La terminal de la portada

Un formulario sin dependencias

El formulario de contacto no usa ningún servicio externo. Detrás hay un microservidor escrito solo con la biblioteca estándar de Python: genera un captcha aritmético propio, firmado para no tener que guardar estado, descarta los bots con un campo trampa, limita los envíos por IP y manda el mensaje por correo. Delante, Nginx pone sus propios límites.

Reportaje

«Sobre mí», contado como en un videojuego

En lugar de un texto largo, la página «Sobre mí» es un diálogo como los de los juegos de rol de toda la vida. Hay un menú de preguntas que se maneja con el ratón o con las flechas del teclado, y las respuestas se escriben letra a letra y se paginan dentro de una caja de tamaño fijo.

Cada respuesta tiene su propia animación del avatar, que entra con una transición de cambio de canal, y suena una música de fondo cuyo volumen la web recuerda para la próxima visita.

Desplegar es hacer git push

No hay panel de control ni integración continua: publicar es empujar la rama principal a un repositorio en el servidor. Un hook copia los archivos a la carpeta que sirve Nginx y pone el dominio en las URLs absolutas.

$ npm run build

$ git push production main

remote: >> Desplegando main ...

remote: >> Despliegue completado

Hasta el error tiene gracia

Si alguien se pierde, la página de error no se limita a un 404 seco: abre un informe de fallo del sistema y confiesa que el gato se ha comido la página.
